## 系统内存与 PCDN 业务运行优化

### 问题与分析

AX3000 产品采用 512M 物理内存。在原有系统配置及业务运行条件下，设备出现内存压力、频繁换页和高 I/O 等待，系统响应卡顿。

分析过程中使用 perf 查看热点，结合 vmstat 等工具检查内存与换页状况，逐步将优化重点落到系统内存布局、内核模块及业务程序占用上。

### 我负责的优化

- **系统内存布局**：重新调整 DTS 中的内存布局，禁用原来开启但未使用的 WiFi Radio 设备描述，释放不必要的预留资源。
- **内核与软件配置**：裁剪不相关的内核组件和软件，减少运行负担。
- **Linux C 业务程序**：修复内存泄漏，减少 C 代码中大量的 Shell 命令调用，重构部分功能模块，降低内存占用。

这些调整分阶段推进。团队同时使用 cgroup 管控第三方业务程序的 CPU 和内存资源，该部分由其他同事实现。

### 结果与测量口径

| 观察项 | 结果及口径 |
| --- | --- |
| 物理内存 | 同一款 512M 硬件 |
| 系统可识别内存 | 新旧系统在开机初期通过 `free` / `MemTotal` 对比，从约 310M 增至 430M，增加约 120M |
| 应用运行占用 | 通过泄漏修复和模块优化降低，未保留统一的下降比例 |
| 系统运行 | 高 I/O 等待与卡顿改善 |
| 业务效果 | 在该硬件上支持 PCDN 业务运行，同时保障用户体验 |

`MemTotal` 表示系统可识别的总内存，与空闲内存、应用占用是不同指标。这里分别记录内存布局调整的效果和运行时占用优化的效果，不将它们折算为笼统的“整体性能提升比例”。

这项系统优化获得无线宝产品部 2024 年上半年卓越服务奖，也是由 P6 晋升 P7 的工作成果之一。

## Mesh 有线回程下，漫游后无法上网

**现象**：客户端完成跨 AP 漫游后，WiFi 连接已恢复，但业务流量无法正常转发。

定位时先排除 Association、DHCP 等连接环节的问题，再检查数据转发路径，确认异常发生在 Controller 侧。通过分析 Linux ARP 表与交换机 FDB 学习状态，发现二层转发表未及时同步，流量仍被发送到旧端口。

完成相关修复后，恢复漫游后的正常通信。

## Beacon 周期异常与 IoT 连接不稳定

**现象**：复杂无线环境下，IoT 设备偶发掉线。

创建 Monitor 接口，通过 tcpdump 抓取 802.11 空口数据，检查 Beacon 周期与无线底噪情况。结合原厂文档分析 CCA 参数影响，调整 CCA Threshold，并验证设备连接稳定性。

该处理改善了对应环境下的连接稳定性，未将参数调整泛化为所有无线环境通用的配置。

## 终端短时离开覆盖范围后无法重新接入

**现象**：终端短时离开 WiFi 覆盖范围，再次进入后无法正常重连。

通过 Monitor 模式抓取 802.11 管理帧，发现 AP 未收到客户端的 Disassociation / Deauthentication 帧。进一步结合系统日志，确认 AP 保留了旧 STA 状态，影响客户端重新关联。

通过优化 STA 状态清理流程，恢复终端自动重连能力。
